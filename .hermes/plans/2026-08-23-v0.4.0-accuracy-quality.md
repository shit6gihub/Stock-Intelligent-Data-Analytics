## 批次一:判断准确性(承重墙)

### P1 级联删除摧毁后验样本(最高优先)
- 现状: refresh_entry_candidates 每日 3 次 DELETE 当日候选重建(entry_candidates.py:1701),
  ID 全换 → EntryCandidateOutcome/StrategyOutcome/FactorSnapshot FK CASCADE 连坐删;
  仅每日最后一轮信号存活进入后验 → 因子标定/策略再平衡学到幸存者偏差样本。
- 修法: 候选按 (snapshot_date, market, symbol) upsert(存在则原行更新, ID 稳定);
  当轮消失的候选改标 status='retired'(不物理删,历史可评估);
  refresh_strategy_signals 的 stale 删除同样改为标 inactive。
- 验证: 单测模拟两次 refresh(第一次 A/B/C, 第二次 B/C/D) → A retired 非 deleted,
  outcome 行保留;active 查询只返回当前代。

### P2 共振加分死代码
- 现状: _apply_resonance_bonus 写 seed meta,但 _score_suggestion 读 ORM suggestion.meta、
  _score_market_scan_candidate 无共振读取 → 排序从未考虑共振。
- 修法: 评分处显式传共振参数(两条路径),加分与 evidence 标注生效。
- 验证: 单测双源命中票 score 高于单源票 +8。

### P3 策略库口径修正(strategies.py + panwatch_strategies.yaml)
- 缺失字段由"跳过该条件"改"该票不通过"(missing_fields 仍记录,非交易时段行为在 UI 已有提示);
- reversal 因子方向修正(今日企稳=change>=0 加分);
- low_pe 对 pe<3(一次性收益异常)降权封顶;
- oversold_reversal 描述与实现对齐(去掉未实现的 RSI/KDJ 金叉表述)。
- 验证: 单测缺失 volume_ratio 的行 volume_breakout 不通过;reversal 方向断言。

### P4 主力意图物理守卫
- 现状: 腾讯逐笔重复计数曾致净额翻倍 47%,盘后哨兵才发现;盘中无守卫。
- 修法: dark_flow 汇总处加守卫 |main_net| > turnover×1.05 → data_status='suspect',
  signal 降级为数据异常提示,不再输出吸筹/派发结论。
- 验证: 单测构造净额>成交额 → suspect。

## 批次二:系统质量

### Q1 调度器 Redis 选主(多 worker 双跑止血)
